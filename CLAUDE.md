# CLAUDE.md

Notes for Claude working in this repository.

## What this project is

Architecture documentation and analyses for a data platform, kept as plain
Markdown and built with Quarto into a website (GitLab Pages), a PDF and
Word document per analysis, and the complete architecture as one document.
The Markdown is the single source of truth. `README.md` explains the layout
and the everyday commands; read it first.

## Rules that keep this consistent

- **British English, plain English.** Colour, organise, catalogue. Expand
  initialisms on first use; explain technical terms in passing. Friendly and
  clear; no business buzzwords. Prose over bullet lists unless a list
  genuinely is a list.
- **Generic naming.** No client names, project names, repository names or
  acronyms from any client's systems. Agreed vocabulary: `platform-qa`,
  `canary-dab`, "environment snapshot", "shared CI/CD pipeline".
- **Terminology, used precisely:** an *environment* is dev/ppr/prd; a
  *workspace* (or *stage*) is sandbox/staging/live. An environment contains
  three workspaces — never the other way round.
- **Product names:** "Declarative Automation Bundles (DABs, formerly
  Databricks Asset Bundles)"; "Lakeflow Declarative Pipelines (formerly Delta
  Live Tables)"; "Auto CDC (formerly `APPLY CHANGES`)". Legacy name once at
  first definitional mention per document.
- **Headings keep their manual numbers** ("# 4. Data products") for wiki
  replication; the build strips them. Don't renumber for the output.
- **One H1 per file.** A new architecture chapter must also be added to
  `architecture/complete.qmd` — the combined document lists chapters
  explicitly; only the website sidebar globs.
- **Cross-references, never typed numbers.** Every heading of note carries an
  ID (`{#sec-chapter-slug}`), referred to as `@sec-chapter-slug`. Never write
  "chapter N" or "section N" by hand. Never let a wrapped line *start* with
  `@ref)`, `@ref.` or `(@ref)` — Pandoc reads it as an example-list marker.
  `python3 scripts/check-refs.py` enforces all of this; run it before
  finishing.
- **Links** between pages are ordinary Markdown links to the source file;
  the build turns them into page links on the website and plain text in PDF
  and Word output.
- **No Mermaid.** Diagrams are hand-authored SVG in the folder's `assets/`
  (house style below) or generated by a Python cell through
  `scripts.platformdata.write_diagram`. Quarto's Mermaid-to-PDF path hangs.
- **Generated content** reads `data/` through `scripts/platformdata.py` only.
  Chapters never parse JSON themselves; if the JSON shape changes, change
  the loader, not the chapters. Cells print Markdown with `#| output: asis`.
- **Formats come from the extension.** Never add `format:` settings,
  filters or LaTeX to individual documents to fix appearance; change the
  `quarto-house` extension and re-install it. Per-document overrides are
  for genuine one-offs (landscape tables, say).
- **Analyses** are dated folders (`analysis/YYYY-MM-slug/index.qmd`) started
  with `make new`. Each records what was decided, why, and what was
  rejected — consequences stated honestly, costs included.

## Diagram house style (SVG)

Canvas `viewBox` ~1080 wide, background `#FAFAF7` (cream). Title centred,
Georgia serif ~30px `#14232A`, 13px `#5D7079` strapline under it; closing
italic caption in Georgia 12px `#5D7079`. Teal box family (fills, white
text): `#367E8D`, `#2A6372`, `#1F4A58`, `#16323E`, darker for later stages.
Amber accent `#C98A2B` for cautions and human decisions (rhombus for
approvals). Neutral outline boxes: cream fill, `#5D7079` stroke 1.5, ink
text `#14232A`. Connectors `#5D7079` 1.6–2px with arrowheads; dashed for
informal relationships. Rounded rectangles rx≈6 (containers rx≈8–12). Body
font `-apple-system, 'Helvetica Neue', Arial, sans-serif`. Convert to PNG and
look before finishing — text collisions are the common defect.

## Building and checking

```sh
make check          # cross-references
make html           # fast: website only
make                # everything, into public/
```

After content changes: render, open the page and (if the document has one)
the PDF you touched, check the table of contents and that no heading still
carries a manual number, and run `scripts/check-refs.py`. Common failures:
`rsvg-convert: not found` (install librsvg); a LaTeX error naming a `.sty`
(TeX package missing — `quarto install tinytex`); a chapter missing from
`complete.pdf` (not listed in `complete.qmd`); a `?@sec-…` in output (ID
not defined anywhere — the checker reports it).
